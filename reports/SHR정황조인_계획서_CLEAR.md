# SHR 정황 조인 계획서 — 카운티 차분이 닫지 못한 마지막 누수에 **구간**을 씌운다

- 작성일: 2026-07-31
- 위치: 카운티차분 계획서 §8-1이 "차분으로 **절대** 닫히지 않는 유일한 누수"라고 적고
  후속으로 넘긴 항목. 그 트랙이 `ρ = +0.083 [+0.056, +0.128]`을 냈으므로 "신호가 있으면
  붙인다"는 조건은 충족됐다.
- 상태: **계획 단계.** 코드 없음. §1의 사전 검사를 통과해야만 §3 이하를 실행한다.

## 0. 한 줄 요약

`Circumstance`(정황)는 Kaggle CSV에 없고 SHR 원본에는 있다. 이것을 **모델 입력에 넣으면
안 된다** — 이 프로젝트의 헤드라인(평면 대 그래프 대비)이 영구히 죽는다. `audit_resources`가
LEOKA에 대해 한 것과 같이 **모델 밖에서** 쓴다. 그리고 기대 효과는 "더 좋은 ρ"가 아니라
**구간**이다:

```
ρ(정황 조정 후)  ≤  진짜 카운티 내부 인종 차별  ≤  ρ(현재) = +0.083
```

지금은 상한 하나뿐이다. 이 트랙은 하한을 만든다.

## 0-1. 안전 조치

카운티차분 §0-1과 동일하되, 이 트랙은 **원본 CSV를 읽는다**는 점이 다르다.

| 규칙 | |
|---|---|
| 1 | 착수 전 `git tag pre-shr-join` |
| 2 | **모델·`E_b`·`z`를 건드리지 않는다.** 기존 지도·`cold_blocks*.csv`·`fairness_*.csv`·보고서 인용 전부 그대로 유효해야 한다 |

## 1. 먼저 죽일 수 있는지 본다 — **정황은 누수일 가능성이 높다**

**이 절이 계획서에서 가장 값어치 있는 부분이고, 한 시간이면 끝난다.**

이 프로젝트의 load-bearing 제약은 목표 누수다. `config.LEAKAGE_COLS`의 가해자 열들이
제외된 이유는 **미해결 사건에서 90~99%가 `Unknown`**이기 때문이다 — 열의 결측 자체가
목표를 알려준다.

**`Circumstance`는 정확히 같은 구조를 가질 수 있다.** SHR에서 정황은 수사기관이
보고하는 값이고, 미해결 사건은 "Circumstances undetermined"로 코딩되기 쉽다. 그러면:

- 모델 입력으로는 당연히 못 쓴다(가해자 열과 같은 이유).
- **외부 감사로도 오염된다.** 미해결일수록 정황이 결측이라면, 정황으로 `E`를 조정하는
  것은 결과를 흡수하는 것이 된다.

그래서 **다른 무엇보다 먼저** 다음 2×2×2를 잰다:

```
P(Circumstance = undetermined | Crime Solved, Victim Race)
```

| 관측 | 판단 |
|---|---|
| 미해결에서 결측률이 해결 대비 크게 높음(가해자 열 수준) | **트랙 중단.** 정황은 이 데이터에서 사후 변수다 |
| 결측률 차이가 작고 **인종별로도 비슷** | 진행. `undetermined`를 별도 범주로 두고 §4 |
| 결측률 차이는 작은데 **인종별로 다름** | 진행하되 결측 자체를 결과로 보고. 그것이 §8-3의 인종차등 기록관행의 직접 증거다 |

세 번째 줄은 트랙의 부산물이 아니라 **독립적인 발견**이 될 수 있다.

## 2. 왜 모델 입력이 아니라 밖인가 — 세 가지 이유, 첫 번째가 결정적

### 2-1. 커밋된 평면 덤프를 재생성할 수 없다 (결정적)

`outputs/predictions/{logreg,xgboost}[_blind].csv` 4개는 **현재 특성 집합으로 학습된
것**이고, `train_baseline.py`는 저장소에서 삭제됐다. `.gitignore`가 이 4개만 예외로
커밋한 이유가 정확히 "재생성 불가"다.

`Circumstance`를 `X`에 넣으면 **GraphSAGE(정황 있음) 대 XGBoost(정황 없음)**이 되어
비교가 무효가 된다. 그러면 죽는 것:

- `graphsage_geo_blind − xgboost_blind = +0.82 [+0.65, +1.03]` (프로젝트의 기제 결과)
- 짝지은 카운티 표준화 대조 `+0.0277 [+0.0206, +0.0345]` (방금 유의하게 만든 것)
- 위 둘을 인용하는 보고서 60곳

**되돌릴 방법이 없다.** 특성을 하나 추가하는 대가로 프로젝트의 헤드라인을 잃는다.

### 2-2. `E_b`가 정황을 흡수하면 z의 정의가 흔들린다

`audit_resources`가 인력에 대해 한 논증 그대로다 — 모델이 "이 카운티엔 갱 관련이 많으니
안 풀릴 것"을 배우면 디트로이트의 이상이 **해결돼서가 아니라 모델이 미리 정상이라고
인정해서** 사라진다. 그리고 갱 관련 살인은 지리적으로 집중되므로, 지도의 헤드라인인
`z ↔ black_share = +0.290`이 통째로 재계산된다.

### 2-3. blind 모델에 새 인종 프록시가 열린다

정황은 인종과 상관된다. `--blind`가 막는 것은 인종 더미이지 프록시가 아니므로, 정황을
넣으면 blind 조건에서 인종 증폭비가 **오를** 수 있다. 이 프로젝트가 진단한 바로 그
경로를 하나 더 여는 셈이다.

> **결론: 모델 입력 버전은 별개 프로젝트다.** 평면 비교를 포기하고 파이프라인 전체
> (`01`~`04` + 전 실험 + 지도)를 다시 돌릴 각오가 있을 때만 의미가 있으며, 그것은
> "정확도를 올리자"는 다른 목표이지 "z를 분해하자"가 아니다.

## 3. 사전 등록

### 3-1. 게이트 둘 (통과 못 하면 중단)

| 게이트 | 기준 | 왜 |
|---|---|---|
| **G1 누수** | §1의 결측률 검사 통과 | 정황이 사후 변수면 트랙 자체가 무의미 |
| **G2 매칭 편향** | 전체 매칭률 ≥ 95% **그리고** White/Black 매칭률 차이 < 1%p | 매칭 실패가 인종과 상관되면 **새 편향**이 들어온다. LEOKA는 `(ORI, 연도)` 100%였지만 이건 사건 단위라 보장이 없다 |

G2가 이 트랙 고유의 위험이다. `audit_resources`에는 없던 것이므로 명시적으로 잰다.

### 3-2. 주 예측

> **정황으로 조정하면 ρ는 내려간다(ρ' < +0.083).** 같은 카운티 안에서도 흑인 피해자
> 사건이 낯선사람·갱 관련 비중이 높고 그 범주들의 검거율이 크게 낮기 때문이다.

**크기는 예측하지 않는다.** "같은 카운티 안에서 인종별 정황 구성이 얼마나 다른가"는
측정 전에 알 수 없고, 여기서 숫자를 적으면 사후 정당화가 된다.

| 결과 | 해석 |
|---|---|
| ρ' > 0, CI가 0 제외 | **이 트랙 최강의 결과.** 카운티 고정 + 사건구성 조정 후에도 인종 격차가 남는다. 남는 누수는 §8-2·§8-3 둘뿐 |
| ρ' ≈ 0 | 카운티 내부 인종 격차는 **사건구성으로 설명된다** — 단, §3-4의 세탁 문제 때문에 "설명"과 "흡수"를 못 가른다. 구간의 하한이 0이라고만 말한다 |
| ρ' > ρ (오름) | 예측 실패. 조인 정렬을 먼저 의심(§7) |

### 3-3. 부차 예측

- **카운티 간 상관이 카운티 내부보다 더 많이 줄어든다.** 갱 관련 살인은 지리적으로
  집중되므로 `z ↔ black_share = +0.290`이 정황 조정에 더 민감할 것이다. (다만 z 자체는
  건드리지 않으므로 이것은 **별도 산출물**로만 낸다 — §0-1 규칙 2.)
- **`undetermined`를 별도 범주로 둔 버전과 제외한 버전의 차이가 작지 않다.** 둘 다 낸다.

### 3-4. 이 트랙이 원리적으로 답할 수 없는 것 — 미리 못 박는다

**"갱 관련"은 사실이 아니라 경찰의 판단이다.** 흑인 피해자 사건을 갱 관련으로 더 쉽게
분류한다면, 정황을 통제하는 것은 차별을 기준선에 세탁하는 것이다 — `detect_cold_blocks`가
인종에 대해, `audit_resources`가 인력에 대해 이미 한 논증의 미묘한 버전이다.

따라서 ρ가 떨어져도 **"사건구성이 설명했다"와 "차별을 흡수했다"를 가를 수 없다.**
그래서 산출물은 점추정이 아니라 **구간**이고, 그것이 이 트랙이 줄 수 있는 전부다.
이 문장은 결과와 함께 반드시 인용한다.

## 4. 설계 — 브래킷을 만드는 법

### 4-1. 정황별 상대위험을 `E`에 곱한다 (1차)

`detect_cold_blocks`의 δ와 같은 계열이다. δ가 **전역** 1-파라미터 보정이라면, 이것은
**정황별** 보정이다:

```
E'_bg = Σ_{i∈b,g} (1 − p̂_cal,i) · r_{c(i)}
```

`r_c`는 정황 범주 c의 상대위험으로, **인종·카운티를 무시하고 전국에서** 적합한다
(`Σ_i (1−p̂_i)·r_{c(i)} = Σ_i (1−y_i)`를 범주별로 만족시키는 값, 즉 범주별
관측/기대 비율). 그러면:

```
ρ' = log(SMR'_Black / SMR'_White),   SMR'_bg = O_bg / E'_bg
```

**`r_c`를 인종과 무관하게 적합하는 것이 핵심이다.** 그래야 "흑인 피해자가 더 어려운
정황에 있다"는 제거되고 "**같은 정황 안에서** 흑인 피해자 사건이 더 안 풀린다"는 남는다.
인종별로 적합하면 격차가 정의상 0이 된다 — `calibrate`의 δ를 인종별로 적합하면 안 되는
것과 같은 이유이고, `clear.predictions.calibrate` docstring이 이미 적어 둔 규칙이다.

### 4-2. 카운티 공변량 회귀 (2차)

`audit_resources --target rho`와 같은 형태. 카운티별로 "인종 간 정황 구성 차이"를 스칼라
κ_b로 요약하고(정황만으로 예측한 검거율의 인종 차이), `ρ_b ~ κ_b`를 본다. 1차와 달리
**카운티 수준 이질성**을 볼 수 있다 — 어떤 카운티에서 정황 차이가 큰지.

1차가 헤드라인, 2차가 보조다. 둘이 크게 어긋나면 구현을 의심한다(§7).

### 4-3. 산출물은 구간이다

```
outputs[/{scope}]/shr_circumstance_bracket.csv
  ρ  (현재, 카운티차분 트랙)            = +0.083 [+0.056, +0.128]   <- 상한
  ρ' (정황 조정, undetermined 별도 범주)                            <- 하한 후보 A
  ρ' (정황 조정, undetermined 제외)                                 <- 하한 후보 B
```

**둘 다 내고 더 보수적인 쪽(0에 가까운 쪽)을 하한으로 인용한다.**

## 5. 데이터와 조인

### 5-1. 조인 키가 생각보다 강하다

원본 Kaggle CSV에 **`Incident`가 있다**(24열 중 하나). MAP 파일이 SHR 파생이므로:

```
(Agency Code, Year, Month, Incident)  -> SHR 사건
  + 피해자 순번/인구학(Victim Sex·Age·Race)으로 다중 피해자 사건 내 행 구분
```

`audit_resources`의 `(ORI, 연도)` 100% 조인보다 세밀하지만, `Agency Code`가 그대로
SHR의 `ori`와 붙는다는 점은 이미 검증돼 있다. **그래도 G2 게이트는 유지한다** — 사건
단위 매칭은 보장이 다르다.

### 5-2. 필요한 파일

- **SHR 원본**: Kaplan 통합본, **openICPSR 100699**
  (*Jacob Kaplan's Concatenated Files: UCR Program Data: Supplementary Homicide Reports*).
  LEOKA의 102180과 **다른 deposit**이다. 무료 계정 로그인이 필요하다.
  - 우리 표본이 1980–2014이므로 **1976–2017을 덮는 V7 이상이면 무엇이든 충분하다.**
    최신은 V16(1976–2024). 버전을 올려도 얻을 것이 없으므로 **받은 버전을 기록해 둔다**
    — 연도 범위가 바뀌면 `r_c` 적합 표본이 달라진다.
  - 목표 열은 `circumstance`(+ 보조로 `situation`). `relationship`은 Kaggle CSV에 이미
    있고 `config.LEAKAGE_COLS`다.
- **둘 자리**: `dataset/geo/`. `.gitignore`의 `dataset/geo/` 규칙이 그대로 적용되므로
  커밋되지 않고, LEOKA와 같은 취급이다(재다운로드 가능한 공개 참조 데이터).

```
dataset/geo/
  LEOKA_parquet_1960_2024_year/     <- 이미 있음 (openICPSR 102180)
  ICPSR_35158/                      <- 있으나 안 씀 (LEAIC, 계획서 §5-2 각주)
  SHR_.../                          <- 여기에 푼다 (openICPSR 100699)
```

## 6. 구현

```
src/experiments/shr_circumstance.py       (새 스크립트 하나)
  1) SHR 로드 + 원본 CSV와 (ORI, 연, 월, Incident) 조인
  2) §1 누수 검사  -> 게이트 G1 (실패 시 즉시 중단, 표는 남긴다)
  3) §3-1 매칭률 검사 -> 게이트 G2
  4) 정황별 상대위험 r_c 적합 (전국, 인종 무관)
  5) county_race_residual의 O/E/V 기계로 ρ' 재계산
  6) outputs[/{scope}]/shr_circumstance_bracket{,_counties}.csv
     results.csv (family=shr_circumstance)
```

**`clear/`에 올릴 것**: `county_race_residual.contrast()`(카운티×인종 O/E/V → ρ)가 이제
호출부 2곳이 되므로 규칙상 올린다. 안 올리면 두 스크립트가 ρ를 각자 정의하게 되고,
그러면 상한과 하한이 **다른 양의 구간**이 된다 — 이 트랙에서는 치명적이다.

`E'` 계산은 호출부가 하나이므로 스크립트에 남긴다.

## 7. 검수

| 검사 | 통과 조건 |
|---|---|
| **G1 누수** | §1의 결측률 표. 판단 기준을 §1에 미리 적어 뒀다 |
| **G2 매칭 편향** | 전체 ≥ 95%, 인종별 차이 < 1%p |
| 행 보존 | 조인 후 행 수 == 638,454(중복 확대 없음). 다중 피해자 사건에서 **행이 늘면** 키가 부족한 것 |
| `r_c` 정합 | `Σ (1−p̂)·r_c == Σ (1−y)` (전역, 1e−6) |
| ρ 재현 | 정황 조정 **없이** 돌리면 `county_race_residual`의 +0.083을 정확히 재현 |
| 1차 vs 2차 | §4-1과 §4-2의 방향이 일치 |
| 무훼손 | `git status`에 기존 tracked CSV 없음 |

**"ρ 재현"이 핵심이다.** 조정 계수를 1로 두면 기존 결과가 그대로 나와야 한다 — 그러면
ρ와 ρ'가 같은 기계에서 나온 같은 양임이 보장되고, 구간이 성립한다.

## 8. 하지 않을 것

- **개별 카운티에 유의성 판정을 붙이지 않는다**(카운티차분 §6-3과 같은 논거).

## 10. 이 트랙이 끝나면 답해지는 것

1. **`ρ = +0.083`의 하한.** 지금은 상한 하나뿐이다(그것도 α=100 편향 때문에 아래로
   치우친 상한이라, 사실은 "한쪽만 아는 점추정"에 가깝다).
2. **카운티 차분이 닫지 못한 누수 셋 중 하나의 크기**(§8-1).
3. **G1의 결과 자체.** 정황이 사후 변수인지 아닌지는 이 데이터셋을 쓰는 누구에게나
   유용한 사실이고, 지금 아무도 모른다.
4. (부산물) 정황 결측이 인종별로 다르면 **§8-3의 인종차등 기록관행에 대한 직접 증거**다.

답해지지 **않는** 것:

- **"설명"과 "흡수"는 끝까지 안 갈린다**(§3-4). 정황이 경찰의 판단인 한, 이 데이터로는
  불가능하다.
- **§8-2의 채널 × 인종 상호작용**은 그대로 남는다.
- **카운티 수준 결손**(`z ↔ black_share = +0.290`)의 정체는 여전히 분리되지 않는다.
  이 트랙은 카운티 **내부** 성분만 다룬다.
