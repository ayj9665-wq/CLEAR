## 0-1. 안전 조치 — 실행 전에 읽을 것

이 작업은 **기존 산출물을 하나도 건드리지 않는다.**

- 새 파일: `src/experiments/build_story_page.py`, 출력

## 1. 설계 원칙 — 기존 지도가 이미 확립한 규율을 상속한다

이 페이지는 새 규율을 만들지 않는다. `build_web_map.py`가 이미 값을 치르고 얻은
네 가지를 그대로 가져온다.

1. **외부 요청 0.** 차트 라이브러리도, 폰트 CDN도, 이미지 URL도 없다. 폰트를 CDN
   대신 서브셋 임베드로 간 이유가 이것이다(§6-1).
2. **어려운 계산은 파이썬에서 끝낸다.** 투영·단순화·구간 경계·색 인덱스는 빌드
   시점에 확정해 정수로 넘긴다. 브라우저는 칠하기와 호버만 한다. `map_figures`에서
   범례 경계가 `searchsorted`와 한 칸 밀렸던 사고가 이 규칙의 출처다.
3. **판정 결과는 불리언으로 확정해서 넘긴다.** CSV 왕복에서 빈 `flag`가 `NaN`이 되어
   143개 카운티를 전부 신호처럼 칠했던 사고를 반복하지 않는다. 브라우저에서 문자열을
   비교하지 않는다.
4. **경고문은 장식이 아니라 산출물의 일부다.** 지도만 본 사람은 반드시 "빨간 카운티 =
   경찰이 일을 안 한다"로 읽는다. 포트폴리오라고 빼면 안 되고, 오히려 "한계를 아는
   사람"이라는 신호가 된다.

   다만 **그대로 재사용하지는 않았다**(계획 변경). `build_web_map.CAVEATS`는 분석을
   읽는 사람을 독자로 가정한 문장이다 — SMR, BH FDR, 간접 표준화, 충돌자(collider)가
   설명 없이 나온다. 이 페이지의 독자는 그렇지 않으므로 `NOTES`(12개)와 `HOWTO`(3개)에
   **같은 내용을 쉬운 말로 다시 썼다.** 쉽게 쓰는 것과 약하게 쓰는 것은 다르므로
   **내용은 하나도 빼지 않았고 숫자도 전부 남겼다.** 예: "간접 표준화한 기댓값 대비
   SMR" → "'이 정도 사건들이라면 대략 이만큼은 미해결로 남는 게 보통'이라는 기댓값을
   먼저 만들고, 실제와 비교한다".

   지도 위에도 **읽는 법 카드 3장**을 앞세운다 — 색이 무슨 뜻인가 / 왜 대부분은 색이
   없나 / 마우스를 올리면 나오는 숫자들(SMR·z·q를 한 줄씩 풀어 씀). 툴팁도 배수를
   먼저 문장으로 바꿔 보여 준다("기대보다 30% 더 미해결"), 원래 값은 그 아래.
   레이어·범례 라벨도 같이 바꿨다("설명되지 않는 잔차" → "기대와의 차이",
   "판정했으나 유의하지 않음" → "따져 봤으나 우연 수준").

여기에 이 페이지만의 원칙 하나를 더한다.

5. **붉은색은 어휘가 아니라 단어 하나다.** 페이지 전체에서 빨강이 등장하는 곳은
   (a) 지도의 cold 카운티, (b) 신뢰구간이 1.0을 넘어선 격차 막대 — 둘뿐이다.
   링크·버튼·호버 상태에는 빨강을 쓰지 않는다(회색조 + 흰색 반전).

## 3. HERO — 지구본은 만들었다가 걷어냈다 (철회)

도트 격자 지구본(Fibonacci 구면 1,400점, 클릭 → 관성 회전 → 북미 정착 → cold 카운티
74곳 붉은 점 점등)을 계획대로 구현했고, 실제로 의도한 대로 동작했다. **그런데 걷어냈다.**

판단 근거는 두 가지다. 지구본이 하는 말("미국 이야기다", "여기 74곳이 있다")은
바로 아래 §4의 카운터와 §6의 지도가 더 정확하게 다시 한다 — **같은 말을 두 번 하는
장치**였다. 그리고 74개 점이 미국 동부에 몰려 지구 표면의 몇 %만 차지하므로, 진짜
정보 밀도는 지도의 1/100인데 화면은 100vh를 먹었다.

대체: **타이포그래피만의 HERO.** 영문 풀네임 라벨 / `CLEAR` / "누가 잊히는가" /
한 줄 요약 / 메타 5개(살인사건 638,454건 · 1980-2014 · 카운티 3,143곳 · GraphSAGE ·
공정성 완화 적용). 그림이 없으므로 크기 대비와 여백이 위계를 전부 진다.

부수 효과: JS 150줄, 마커 좌표 2KB, `cold_markers()`/`_ring_centroid()`가 사라졌다.
페이지에서 움직이는 것은 이제 스크롤 등장과 지도 호버뿐이다.

**남겨 둘 만한 기술 메모** — 다시 필요해지면: 회전은 유효 경도를 `경도 + yaw`로 만들므로
정면에 놓을 목표 yaw는 `-경도`다(미국 중앙 −98° → yaw +98°). 정사영에서 구로 읽히게
하는 것은 점 크기가 아니라 **깊이 알파 감쇠**(`0.07 + 0.88·z^1.7`)다. 그리고 클릭을
기다리면 안 된다 — 손 안 대는 관람객이 기본값이라 8초 후 자동 발화가 필요했다.

## 4. 스크롤 서사 — 각 섹션이 담을 숫자를 미리 확정한다

포트폴리오에서 가장 흔한 실패는 "열심히 했습니다"만 남고 **주장이 없는** 것이다.
섹션마다 **주장 한 문장 + 수치 하나 + 그 수치를 못 믿을 이유 하나**로 고정한다.

### S1 — 문제

> 미국 살인사건의 30%는 끝내 범인이 잡히지 않는다. 그런데 **어디서** 안 잡히는지는
> 균일하지 않다.

카운터 4개(스크롤 진입 시 롤업 애니메이션): `638,454`건 / `1980–2014` / `29.8%` 미해결 /
`3,090` 카운티.

### S2 — 접근

예측 → 진단 → 처방 → 적용의 4단 다이어그램. **한 질문을 세 단계로 판다**는 구조
자체가 이 프로젝트의 형태이므로 여기서 한 번에 보여준다. 각 칸은 클릭 시 해당 섹션으로
스크롤(앵커).

### S3 — 예측: 그래프가 왜 이기나

| 모델 | MCC | AUC | Balanced Acc |
|---|---|---|---|
| GraphSAGE (geo) | **0.285** | **0.712** | 0.653 |
| XGBoost | 0.274 | 0.703 | 0.647 |
| LogReg | 0.233 | — | — |

여기에 **이 프로젝트만 할 수 있는 말**을 붙인다:

> 마진이 아니라 **마진 ÷ 시드 노이즈**로 판단한다. MCC는 19배, AUC 14.6배, Balanced
> Accuracy 6.6배 — 주장 가능. Precision(1.2배), F1(0.0배), Specificity(0.7배)는
> **주장하지 않는다.** 좋아 보이는 숫자를 스스로 버린 표다.

그리고 그래프가 도움이 되는 **이유**: 랭킹 실험 결과(이웃을 유사도로 고르면 오히려
나빠진다, MCC −0.0054 = 시드 표준편차의 9배). 이웃 평균과 자기 자신의 코사인이
0.64 → 0.95로 올라가 GNN이 MLP로 퇴화한다.

> 그래프의 가치는 **유사성이 아니라 맥락 집계**다. 블록 안 무작위 이웃 20개는
> "이 카운티는 어떤 곳인가"의 비편향 추정치다.

### S4 — 진단: 두 민감속성이 다르게 답한다

증폭 사다리(가로 막대 3단, 1.0 기준선 표시):

| | pooled | 주 표준화 | **카운티 표준화** |
|---|---|---|---|
| 인종 | 1.805 | 1.558 | **0.662** [0.452, 0.888] |
| 성별 | 1.246 | 1.005 | — |

주장:

> **성별 격차는 컬럼이고, 인종 격차는 그래프다.** 성별은 변수를 지우면 사라진다
> (2.55–3.29 → 0.88–0.96). 인종은 안 사라진다 — blind GraphSAGE 1.48 vs blind
> XGBoost 0.67, 짝지은 차이 **+0.82 [+0.65, +1.03]**. 같은 모델을 비동류 그래프
> (temporal)에 올리면 0.36으로 내려간다. 남는 경로는 인종 동류성이 높은 geo 엣지뿐이다.

그리고 카운티 표준화에서 0.662로 떨어지는 것이 **반증이 아니라 확증**임을 한 문장으로:
City가 곧 geo 블로킹 키이므로, 카운티를 고정하면 그 경로가 통째로 사라지는 것이 맞다.

여기에 카운티 차분의 두 번째 결과:

> 같은 카운티 안에서 흑인 피해자 사건은 기대 대비 **8.7% 더** 미해결로 남는다
> (log-SMR비 +0.083 [+0.056, +0.128]). 그런데 그 값과 카운티 흑인 비중의 상관은
> **0**이다(−0.015). 즉 격차는 어디에나 균일하고, 지도의 색은 **카운티 사이**의
> 이야기다.

### S5 — 처방: 되갚을 수 있는가

트레이드오프 곡선(α 사다리). 전국 α=100에서 FPR 증폭 1.8 → 0.261, 비용 −0.0156 MCC.

솔직한 부분을 뺄 이유가 없다:

> 이 게이트는 **pooled** 지표로 통과했고, 주 표준화하면 0.590 [0.456, 0.738]로 어떤 α도
> 통과하지 못한다. 벌점 자체가 pooled 격차로 정의돼 있어 더 세게 눌러도 단조롭지
> 않다(α=25/50/100 → 0.639/0.701/0.590). **노브를 더 돌리는 게 답이 아니라 층화 벌점이
> 필요하다**는 것이 지금까지의 결론이다.

### S7 — 한계

`build_web_map.CAVEATS` 7개를 아코디언으로. 여기에 포트폴리오용 두 개를 더한다:

- **재수사 우선순위 목록은 계산했지만 배포하지 않는다.** 검증 경로가 없고(재수사 결과
  컬럼이 없다), 모델이 카운티를 모르는 것이 블록 단위에서는 의도된 설계지만 개별 사건
  단위에서는 오염이며, MCC 0.30에서 개별 사건 출력은 잡음이 지배한다. **감사 통계만
  낸다.**
- **정황 변수로 사건 구성을 통제할 수 없다.** SHR 조인은 96.10%로 성공했지만, 기록된
  정황은 결과의 **하류**라 충돌자(collider)다 — 미해결 사건에서 "미확정" 코딩이 흑인
  피해자 쪽에 카운티를 고정해도 **+4.1pp [+2.0, +6.8]** 더 많다. 통제하면 "기록을 덜
  했다"를 사건 구성으로 세탁하게 된다. **닫히지 않는 누수라는 것이 결론이다.**

난독화(`[at]` 치환, JS 조립)는 하지 않는다 — 공개 포트폴리오에서 연락처가 복사되지
않는 쪽이 더 손해다.

## 5. 지도 섹션 — 주인공

### 5-1. 코드 재사용 경계

```python
# src/experiments/build_story_page.py
from experiments.build_web_map import (

```

**데이터 함수만 가져오고 HTML 템플릿은 새로 쓴다.** `build_web_map.HTML`은 밝은 배경
전용이고 이 페이지는 어둡다. 템플릿을 파라미터화하려 들면 조건 분기가 늘어 두 산출물이
같이 깨진다 — 지금 구조에서는 **템플릿 중복이 결합보다 싸다.** 대신 값을 만드는 쪽
(구간 경계, 색 인덱스, 판정 상태)은 한 곳에 있으므로 범례와 그림이 어긋나는 사고는
구조적으로 막힌다.

기본 소스는 **`cold_blocks_cv5.csv`**(크로스피팅, 1,803 카운티). 이유는 이미 문서화돼
있다 — 작은 카운티가 구조적으로 빠지는 지도는 "누가 잊히는가"에 답할 수 없다. 4개
카운티(Lauderdale TN, Greensville VA, Pulaski MO, Grenada MS)는 표 전체에서 가장 강한
SMR인데 test 지도에서는 보이지 않는다.

### 5-2. 팔레트 — 빨강만 남긴다

`clear/counties.py`에 함수 하나를 더한다:

```python
def gray_arm(blue_arm=None):
    """파랑 팔과 **OKLab 명도를 맞춘** 무채색 팔. chroma=0, L은 그대로."""
```

파랑 팔의 각 단계에서 `hex_to_oklab` → `(L, 0, 0)` → `oklab_to_hex`. 이러면
빨강 팔이 이미 지키고 있는 **팔 간 명도 대칭**(최악 오차 0.00105)이 회색 팔에도
그대로 성립한다. 발산 스케일의 기하는 하나도 안 바뀌고 채도만 죽는다.

```
palette = [NEUTRAL] + gray_arm(5) + red_arm(5)     # 0=미판정 회색, 1..5=회색(warm), 6..10=빨강(cold)
```

`color_tables()`가 반환하는 인덱스 구조를 그대로 쓰므로 **인덱스 재계산이 없다.**
바뀌는 것은 `palette` 리스트 한 줄뿐이다.

**대가를 명시한다:** warm 카운티("기대보다 잘 해결")의 강도 대비가 약해진다. 방향
정보는 남지만(회색 vs 빨강) 크기 비교는 어려워진다. 범례에 그 사실을 쓰고, 정확한
값은 호버/표에서 읽게 한다. 표는 그대로 전량 유지한다.

#### 구현 결과 — 밝기를 맞추면 규칙이 뒤집힌다 (계획 수정)

위 설계대로 chroma만 0으로 만들어 그려 봤더니 **의도와 정반대 그림이 나왔다.** 밝은
표면 위에서 **같은 밝기라면 무채색이 유채색보다 대비가 세다.** 파랑 팔의 가장 어두운
단계 L=0.338을 그대로 회색으로 옮기면 `#4a4a4a`가 나오는데, 흰 카운티들 사이에서 이게
같은 밝기의 빨강보다 훨씬 강하게 튄다. 실제 렌더에서 캘리포니아·네바다의 warm 카운티가
화면을 지배하고 정작 cold 카운티가 옅어 보였다 — "빨강만 경보"가 "회색이 경보"가 된 것이다.

**수정: 밝기를 아핀 압축한다.** `gray_arm(l_floor=0.66)`이 L 범위 [0.905, 0.338]을
[0.905, 0.66]으로 옮긴다. 단계 간 상대 간격은 보존되므로 순서와 단조성은 그대로이고
팔 전체가 조용해질 뿐이다. 실제 팔레트:

```
warm(회색)  #dfdfdf #cccccc #b8b8b8 #a5a5a5 #929292
cold(빨강)  #fbd6d2 #f5938c #ec393e #a72629 #671315
```

**발산형의 "양 팔 밝기 대칭"을 의도적으로 깬다.** 그 요건은 부호를 대칭적으로 읽는
지도를 위한 것이고, 이 페이지는 한쪽 부호만 경보로 읽히길 원하므로 요건 자체가 다르다.
`map_figures`/`build_web_map`의 팔레트는 손대지 않았으므로 그쪽 대칭은 그대로다.

이건 **렌더해서 눈으로 보기 전에는 안 보이는 종류의 문제**였다(map_figures의 버그 셋과
같은 계열). 검사기는 "warm 팔이 무채색인가"는 재지만 "위계가 뒤집혔는가"는 재지 않는다.

### 5-3. 어두운 페이지 위의 밝은 지도 카드 — 권고

발산 팔레트는 **밝은 배경 기준으로 명도가 검증**돼 있다(파랑 0.905 → 0.338, 중립
0.952). 검정 위에 그대로 얹으면 가장 밝은 단계(약한 신호)가 가장 강해 보인다 —
의미가 뒤집힌다.

두 선택지:

- **(권고) 지도 섹션만 밝은 카드로 반전.** `#f7f7f5` 패널을 어두운 페이지 안에 깐다.
  검증된 팔레트가 무손상이고 재검증 비용 0. 레퍼런스 사이트도 이미지·제품 패널에서
  같은 반전을 쓴다. 섹션 전환 자체가 "여기부터 데이터"라는 신호가 된다.
- (대안) 어두운 배경용 램프를 새로 만든다 — 명도 방향을 뒤집고 OKLab 대칭을 다시
  검증해야 한다. 그림 하나 때문에 검증된 자산을 다시 만드는 값이 크다.

**권고안으로 진행하되, 지도까지 검게 가길 원하면 알려 달라.**

### 5-4. 호버 확대 애니메이션 — 이웃에 구멍을 내지 않는 방법

요구사항은 "마우스를 대면 조금 커지는" 것이다. 코로플레스에서 `<path>`를 그 자리에서
확대하면 **인접 카운티와의 경계에 겹침·틈**이 생겨 지도가 찢어져 보인다.

구현:

1. SVG에 `<g id="hover">`를 **맨 위에** 하나 둔다(항상 비어 있음).
2. `mouseenter` → 원본 path를 `cloneNode`해 `#hover`에 넣는다. 원본은 그 자리에
   그대로 있으므로 아래 지도에는 구멍이 안 생긴다.
3. 클론에 `transform-box: fill-box; transform-origin: center;` +
   `transform: scale(1.08)`, `transition: transform 120ms cubic-bezier(.2,.7,.3,1)`,
   테두리 `stroke-width: 1.6`, `filter: drop-shadow(0 2px 6px #0006)`.
4. `mouseleave` → `#hover` 비우기. 툴팁 페이드아웃.

**부수 효과가 실제 문제를 푼다.** 상위 cold 카운티 상당수가 독립시(Richmond,
St. Louis city, Baltimore city)라 전국 코로플레스에서 면적이 거의 0이다 — 강도가
약한 게 아니라 **안 보이는** 것이다. 호버 확대는 이 결함에 대한 직접적인 완화책이고,
그래서 이 애니메이션은 장식이 아니라 기능이다.

**터치 기기**에는 `hover`가 없다. `@media (hover: hover)`로 분기하고, 터치에서는
탭 = 확대 + 툴팁 고정, 바깥 탭 = 해제로 처리한다.

추가 반응형 디테일(전부 CSS/JS, 데이터 증가 없음):

- 표 행 호버 ↔ 지도 카운티 하이라이트 **양방향 연동**.
- 섹션 진입 시 지도가 아래에서 살짝 올라오며 페이드인(`IntersectionObserver`,
  `prefers-reduced-motion`에서 비활성).
- 카운터·막대는 화면에 들어올 때 한 번만 애니메이션(재진입 시 반복 안 함 — 반복되면
  싸구려로 보인다).

### 5-5. 컨트롤 — 무엇을 남기고 무엇을 뺄까

**레이어마다 '이게 무엇을 세는지' 한 줄이 뜬다.** 세 레이어는 서로 다른 것을 재는데,
버튼만 있으면 같은 대상을 다르게 칠한 것으로 읽힌다. 실제로 걸린 질문이 이거였다 —
"기대보다 40% 더 미해결인데 왜 '다시 볼 사건'은 0.5%뿐인가".

답은 셋이 겹쳐 있다. (1) 배수의 분모는 **기대 미해결 건수**이지 전체 사건이 아니다 —
뉴올리언스는 배수 1.40이지만 초과분 1,113건은 전체 7,847건의 14.2%다. (2) 우선순위는
**전국 상위 10% 문턱을 넘는 개별 사건**을 센다. 모든 사건이 조금씩만 기대에 못 미치면
초과분은 커도 문턱을 넘는 사건은 0이다. (3) 결정적으로 **모델은 카운티를 모르므로**
카운티의 결손이 개별 p̂을 밀어 올리지 못한다 — 우선순위 밀도는 사실상 그 지역의 사건
구성을 잰다.

측정으로 확인한 것: 배수 ↔ 우선순위 비율 +0.672(방향은 같다), 평균 풀릴 확률 ↔ 미해결
중 우선순위 비율 +0.683, 사건 수(log) ↔ 평균 풀릴 확률 −0.473. 즉 **큰 도시일수록 두
값이 벌어진다** — 뉴올리언스는 미해결의 1.0%만 문턱을 넘고, 시골 로더데일은 82.4%다.

| 기능 | 유지 | 이유 |
|---|---|---|
| 최소표본 슬라이더 (20/50/100) | **유지** | 필터가 아니라 **검정을 세 번 돌린 결과**다. 빼면 결과의 표본 민감도를 감춘 것이 된다 |
| 레이어 전환 (잔차 z / 우선순위 밀도 / 원시 검거율) | **유지** | "원시 검거율"과 "잔차"가 다른 그림이라는 게 이 프로젝트의 핵심 |
| 정렬 가능한 표 | **유지** | 작은 카운티를 읽는 유일한 경로 |
| 호버 툴팁 | 유지 + 확대 애니메이션 |  |

즉 **기능은 하나도 빼지 않는다.** 포트폴리오라고 줄이면 "예쁜 그림"이 되고, 이
지도의 값은 독자가 직접 기준을 흔들어 볼 수 있다는 데 있다.

### 6-1. 폰트 — 외부 요청 0 원칙과 정면 충돌하는 부분

NanumSquare는 웹 표준 시스템 폰트가 아니므로 보통 CDN `<link>`로 부른다. 그러면
**이 페이지의 1번 원칙이 깨진다** — 네트워크가 없거나 CDN이 막히면 폰트가 통째로
빠지고, 이 저장소가 지도에서 지켰던 "파일 하나로 완결"이 무너진다.

**결론: 서브셋해서 base64로 인라인한다.** CDN은 안 쓴다.

이게 가능한 이유는 **이 페이지의 텍스트가 빌드 시점에 전부 확정**되기 때문이다.
런타임에 새로 만들어지는 문자열은 숫자 포맷팅과 카운티·주 이름(라틴)뿐이고, 한글
레이블은 전부 소스에 있다. 즉 **필요한 글리프를 정확히 셀 수 있다.**

#### 조달 — 다운로드가 없다

**NanumSquare_ac 4굵기가 이미 로컬에 설치돼 있다** (각 3,612 글리프):

```
C:/Users/<user>/AppData/Local/Microsoft/Windows/Fonts/
  NanumSquare_acL.ttf   Light      300
  NanumSquare_acR.ttf   Regular    400
  NanumSquare.ttf       Bold       700
  NanumSquare_0.ttf     ExtraBold  800
```

한 벌로 통일한 덕에 **Pretendard 7.4MB 다운로드, `dataset/fonts/` 캐시, 라이선스
확인 대상 2개가 전부 사라졌다.** 빌드가 네트워크에 의존하지 않는다.

#### 굵기 3단으로 위계를 만든다

서체가 하나이므로 위계는 전부 굵기·크기·자간이 진다.

| 층위 | 굵기 | 용도 |
|---|---|---|
| HERO 타이틀 / 섹션 헤드 | **800 ExtraBold** | `CLEAR`, `01 THE PROBLEM`, 카운터 숫자 |
| 소제목 / 강조 / 표 헤더 | **700 Bold** | `<b>`, 수치 강조, 범례 |
| 본문 / 표 / 툴팁 | **400 Regular** | 나머지 전부 |

**Light 300은 안 싣는다.** 어두운 배경에서 얇은 획은 헤일레이션으로 뭉개진다 —
`#f2f2f0` on `#08080a`에서 300은 읽히지 않는다. 굵기 하나 아끼는 것은 덤이다.

NanumSquare는 원래 제목용 성격이 강한 고딕이라 장문 본문에는 Pretendard보다 불리하다.
이 페이지의 문단이 짧다는 점(§4의 "주장 한 문장 + 수치 하나" 구조)이 그 불리함을 대부분
상쇄하지만, 보정은 한다: **본문 16px / `line-height: 1.75` / `letter-spacing: -0.01em`.**
기본 14px·1.6(기존 지도 CSS)을 그대로 쓰면 답답하게 읽힌다.

#### 숫자 정렬 — 걱정할 필요가 없었다

이 페이지는 표와 카운터가 많아 자릿수가 흔들리면 안 된다. NanumSquare에는 `tnum`
피처가 **없어서**(`GSUB`: aalt/dlig/fwid/nalt/pwid/sinf) `font-variant-numeric:
tabular-nums`가 아무 일도 안 한다. 그런데 **숫자 10자의 advance가 전부 600/1000으로
이미 균등폭**이라 결과적으로 정렬이 맞는다. CSS 선언은 무해하므로 남겨 두되,
**정렬을 그 선언에 의존하지 않는다**는 사실을 기록해 둔다 — 폰트를 갈면 이 성질이
같이 사라진다.

#### 실측 크기 — 굵기별로 다른 문자 집합을 깎는다

본문 400은 전체 문자가 필요하지만 타이틀 800은 150자 남짓이면 된다. **굵기마다 그
굵기로 렌더되는 텍스트만** 서브셋한다(공통 집합으로 세 벌을 깎으면 각 66KB, 합
264KB로 1.5배가 된다).

| 굵기 | 글리프 | WOFF1 | base64 | woff2 추정 |
|---|---|---|---|---|
| 400 본문 | ~480 | 52.5KB | 70.0KB | ~42KB |
| 700 강조 | ~390 | 46.6KB | 62.2KB | ~37KB |
| 800 타이틀 | ~185 | 30.3KB | 40.4KB | ~24KB |
| **합계** | | | **~172KB** | **~105KB** |

실제 페이지 텍스트(`build_web_map`의 경고문 + 본문)로 `fontTools.subset`을 돌려 잰
값이다. 추정치가 아니다.

**빌드 실측(최종)은 이보다 작다** — 페이지 본문이 계획서보다 짧기 때문이다:

| 굵기 | 글리프 | woff2 | base64 |
|---|---|---|---|
| 400 | 421 | 36.7KB | 49.0KB |
| 700 | 309 | 31.1KB | 41.5KB |
| 800 | 168 | 23.1KB | 30.7KB |
| **합계** | | | **121.3KB** |

`brotli`는 결국 사용 가능해서 **woff2로 저장됐다**(WOFF1 폴백 경로는 타지 않았다).
최종 페이지 **829KB / 상한 850KB**.

이 때문에 빌드가 **어느 문자열이 어느 굵기로 렌더되는지 알아야 한다.** 템플릿에서
텍스트를 문자열 상수로 다루지 말고 `(text, weight)` 쌍으로 다룬다 — 이게 §7 구조에
반영된다.

#### 빠진 글자 6개를 미리 찾았다

실제 페이지 텍스트의 유니크 문자 586자를 cmap과 대조한 결과 **6자가 없다**:

| 문자 | 코드포인트 | 어디에 | 처리 |
|---|---|---|---|
| `−` | U+2212 MINUS SIGN | `−0.0156 MCC` 등 **수치 전반** | **ASCII 하이픈(U+002D)으로 정규화.** 폰트에 있다 |
| `≈` | U+2248 | `α≈50` | 시스템 폴백 허용 |
| `州` | U+5DDE | 경고문 "주(州)를 통제한" — **실제 페이지 내용** | 시스템 폴백 허용 |
| `球` `豆` `腐` | | 이 계획서에만 등장, 페이지엔 없음 | 해당 없음 |

**U+2212만 정규화하고 나머지는 폴백에 맡긴다.** 브라우저는 글리프 단위로 폴백하므로
두부(`□`)가 아니라 Malgun Gothic으로 렌더된다. 다만 마이너스는 숫자 문자열 한가운데
있어 한 글자만 다른 서체가 되면 눈에 띄므로 정규화한다.

**이게 §6-1 커버리지 검사가 실제로 잡아낸 것이다** — 계획 단계에서 걸렸으니 빌드
단계에서도 걸린다. 검사는 "빠진 글자 0"이 아니라 **"허용 목록(≈, 州)에 없는 빠진
글자 0"**으로 짠다.

#### 빌드가 2패스가 된다 — 이게 이 절의 핵심

서브셋은 **본문 텍스트가 확정된 뒤에** 해야 한다. 따라서 빌드 순서가 뒤집힌다:

```
1) 데이터 로드 → 본문/표/툴팁 텍스트 전부 생성 (폰트 없이)
2) 생성된 문자열 전체에서 유니크 코드포인트 수집
   + ASCII 전체 + 문장부호 + 숫자 (JS가 만들 수 있는 것들의 안전 여유)
3) fontTools.subset으로 각 폰트를 그 집합으로 깎는다
4) base64로 @font-face에 심는다
5) 최종 HTML 조립
```

**3번에서 커버리지 검사를 하고, 하나라도 빠지면 빌드를 실패시킨다.** 조용히 두부(豆腐,
`□`)로 렌더되는 것이 이 방식의 유일한 실패 모드이고, 검사 한 줄로 막힌다.

#### 폴백 스택

```css
--sans: "NanumSquare_ac", -apple-system, "Segoe UI", "Malgun Gothic",
        system-ui, sans-serif;
```

임베드가 어떤 이유로든 실패해도 페이지는 시스템 한글 폰트로 정상 렌더된다.
`font-synthesis: none`으로 가짜 볼드를 끈다 — 안 끄면 700/800이 빠졌을 때 400을 뭉갠
글자가 나오고, 그게 임베드 실패보다 더 알아채기 어렵다.

#### 6-2. brotli 의존성 — 이제 선택 사항이다

`fontTools`는 있지만 **`brotli`가 없어 woff2를 쓸 수 없다.** `pip install brotli`
한 줄이면 되고 총 172KB → 105KB로 줄지만, **WOFF1로도 합계 814KB라 상한 850KB
아래**다(§2). 즉 이건 이제 용량 이득일 뿐 전제 조건이 아니다.

**woff2를 우선 시도하고 brotli가 없으면 WOFF1로 자동 폴백**하도록 짠다. 빌드가
환경 때문에 죽지 않게 하는 쪽이 67KB보다 중요하다.

#### 6-3. 라이선스

폰트가 하나로 줄어 확인할 대상도 하나다.

**NanumSquare**는 네이버 무료 배포 폰트로, 임베드·재배포가 허용되는 것으로 알려져
있으나 OFL과 조항이 같지는 않다. 고지를 HTML 주석과 크레딧 섹션 양쪽에 싣되,
**공개 배포 전에 현행 라이선스 문구를 한 번 확인**하는 것을 권한다. 문제가 되면
`--fonts none`으로 시스템 스택만 쓰는 빌드가 나오고, 페이지는 172KB 가벼워진다.

로컬 시스템 폰트 폴더에서 파일을 읽는다는 점도 기록해 둔다 — 다른 기계에서
빌드하려면 NanumSquare가 설치돼 있거나 `--fonts_dir`로 경로를 넘겨야 한다. 못 찾으면
**폴백 스택으로 조용히 진행하지 않고 경고를 찍는다**(조용한 폴백은 이 저장소가
`--blind` no-op에서 이미 한 번 당한 실패다).

## 7. 구현

### 7-1. 새 스크립트 하나

```
src/experiments/build_story_page.py       약 550줄
```

CLI:

```bash
CLEAR_SCOPE=national python -m experiments.build_story_page
CLEAR_SCOPE=national python -m experiments.build_story_page \
    --src cold_blocks_cv5.csv --simplify_km 1.5 --out clear_story.html
```

기본값은 cv5 / 1.5km / `clear_story.html`. `--src`를 바꾸면 캡션도 같이 바뀐다
(`SPLIT_NOTES` 재사용) — `build_web_map`이 이미 세운 규칙이다.

구조:

```
build_story_page.py
├─ SECTIONS      : 본문 텍스트와 수치를 담은 상수 (숫자는 여기 한 곳에만)
├─ cold_markers(): cold 카운티 74개의 lon/lat 중심 (지구본 마커용)
├─ 데이터        : build_web_map의 load_blocks / build_paths / color_tables 호출
├─ palette       : [NEUTRAL] + gray_arm(5) + red_arm(5)
├─ [1패스] HTML 본문 조립 — 텍스트를 **(문자열, 굵기)** 쌍으로 누적
├─ _fontpack.py  : 굵기별 문자 집합 → 서브셋 3벌 → base64 → @font-face
└─ [2패스] 최종 HTML : globe(150줄) + map(180줄) + scroll(60줄), 전부 인라인
```

**"어느 텍스트가 어느 굵기인가"를 빌드가 알아야 한다**(§6의 굵기별 서브셋). 템플릿에
문자열을 그냥 박으면 이 정보가 사라지므로, 텍스트를 낼 때 굵기를 함께 기록하는 얇은
수집기(`emit(text, weight=400)`)를 하나 둔다. 표·툴팁처럼 JS가 조립하는 텍스트는
**호출부에서 굵기를 선언**한다 — 표 헤더 700, 셀 400 식으로.

빠뜨렸을 때의 실패는 조용하지 않다: 커버리지 검사가 "700 서브셋에 이 글자가 없다"로
빌드를 세운다.

**폰트 코드는 별도 모듈(`experiments/_fontpack.py`)로 뺀다.** `clear/`에는 안 올린다 —
호출자가 하나뿐이라 이 저장소의 "2개 이상" 규칙에 못 미친다. 다만 `build_story_page.py`
본문에 두면 서브셋·base64·라이선스 처리가 서사 조립 코드와 뒤섞여 550줄이 800줄이
되므로, 같은 패키지 안의 별도 파일로 둔다.

**수치는 상수 한 곳에만 둔다.** 본문에 하드코딩된 숫자가 CSV와 어긋나는 것이 이런
페이지의 전형적 사고이므로, 검증 가능한 것(카운티 수, cold/warm 개수, 상관계수,
상위 카운티)은 **CSV에서 읽어 채운다.** 읽을 수 없는 것(증폭 사다리, 모델 표)은
상수로 두되 출처 파일명을 주석으로 남긴다.

### 7-2. `clear/`에 올릴 것과 안 올릴 것

- **올린다**: `counties.gray_arm()` — 색 시스템은 이미 `counties.py`가 소유하고 있고,
  명도 매칭 규율이 거기 문서화돼 있다. 다른 곳에 두면 그 규율에서 떨어져 나간다.
- **안 올린다**: 지구본 수학, 스크롤 로직, 섹션 텍스트 — 호출자가 하나뿐이다.
  이 저장소의 규칙은 **호출자 2개 이상**이다.

## 8. 검증 계획

브라우저 없이 검증할 수 있는 것과 없는 것을 나눈다. `build_web_map`이 밟은 절차를
그대로 따른다.

**자동(스크립트 `--selftest`)**

1. `node --check`로 인라인 JS 문법 검사.
2. 방출된 path를 파이썬으로 되읽어 재렌더 → 원본 폴리곤과 좌표 일치.
3. 데이터 불변식:
   - `len(paths) == 3,090`, 판정 카운티 수 == CSV의 min_n=20 행 수(1,803)
   - cold/warm 개수 == CSV 집계(74 / 276)
   - 색 인덱스가 [0, 10] 범위, 유의하지 않은 카운티는 전부 인덱스 0
   - **6..10(빨강)은 `z > 0` 카운티에만** 등장 — 빨강 규칙의 기계적 검사
   - 본문에 삽입된 숫자 == CSV에서 재계산한 값
   - 지구본 마커 수 == cold 카운티 수(74)
   - 외부 요청 0: HTML에 `http://` / `https://` / `//cdn` 문자열 부재
     (base64 `data:font/woff2` 는 예외로 허용 — 정규식에서 제외)
4. **폰트 검사** (§6-1):
   - **굵기별로** 그 굵기로 렌더되는 모든 코드포인트가 해당 서브셋의 cmap에 있다.
     허용 목록(`≈`, `州`)에 없는 누락이 하나라도 있으면 빌드 실패
   - 본문에 U+2212(`−`)가 남아 있지 않다 — 정규화가 실제로 돌았는지
   - `@font-face` 3개 각각의 base64가 유효한 시그니처로 시작한다(`wOF2` / `wOFF`)
   - 폴백 스택에 `system-ui`가 남아 있고 `font-synthesis: none`이 선언돼 있다
   - 숫자 10자의 advance가 전부 같다(균등폭 전제가 깨졌는지 — 폰트를 갈면 깨진다)
5. 파일 크기 < 850KB.

**브라우저 검사 — 실제로 돌렸다 (계획 갱신)**

이 기계에 크롬이 있어서 헤드리스로 **렌더해서 보고, DOM 상태를 조회**할 수 있었다.
계획 단계의 "내가 못 하는 것"이 대부분 가능해졌다.

```bash
chrome --headless=new --disable-gpu --screenshot=out.png --window-size=1440,900 \
       --virtual-time-budget=11000 "file:///.../clear_story.html"
chrome --headless=new --dump-dom ...      # DOM/상태 조회
```

렌더가 잡아낸 것 넷 — **전부 검사기를 통과한 상태에서 눈으로만 보이던 것들**이다:

1. HERO에서 본문이 지구본 위에 겹쳐 안 읽혔다 → 2단 레이아웃(텍스트 좌 / 지구본 우).
2. 정착 후에도 "클릭해서 지구를 돌려 보세요"가 그대로 떠 있었다(`hint()` 논리 반전)
   → 정착하면 "아래로 스크롤"로 바뀐다.
3. 회색 팔이 빨강보다 강했다 → §5-2 수정.
4. 증폭 막대가 값과 무관하게 전부 빨강이라 **완화에 성공한 막대까지 경보색**이었다
   → 신뢰구간이 1.0을 넘어설 때만 빨강(성별 주 표준화 1.005 [0.925, 1.090]은 회색).

DOM 조회로 확인한 것: `#hl` 복제 1개 + `class="on"` + `matrix(1.09,…)`(호버 확대가
실제로 걸린다), 툴팁 opacity 1, 표 1,800행, 범례 4항목, 카운티 path 3,143개.

**호버 확대에서 `requestAnimationFrame`을 쓰면 안 된다는 것도 이 검사가 잡았다.**
클론을 붙인 뒤 다음 프레임에 클래스를 걸면 프레임이 늦거나 스로틀될 때 확대가 통째로
빠진다(헤드리스에서 실제로 `class=null`로 잡혔다). `getBoundingClientRect()`로 리플로우를
강제하고 동기적으로 거는 방식으로 바꿨다.

**여전히 사람이 봐야 하는 것**: 지구본 회전 속도의 체감, 호버 확대 배율(1.09가 적당한지),
섹션 전환 속도. 열어 보고 이 셋만 알려 주면 조정한다.

**부수 발견 — 기존 배포 지도의 결함. (고쳤다)** 같은 방법으로 `map_national.html`을
조회했더니 **범례 0항목 / 표 0행**이었다. `build_web_map.py`의 `legend()` 첫 줄
`const d=D[LV[li]];`에서 `D`가 어디에도 정의돼 있지 않아 `ReferenceError`가 나고,
`paint()`가 카운티를 칠한 직후 거기서 멈춘다. 색은 칠해지므로 지도는 그럴듯해 보이지만
**범례와 표가 통째로 비어 있었다.** 세 지도 전부 그랬다.

§0-1의 "`build_web_map.py`를 건드리지 않는다"는 회귀 위험을 막자는 조항이지 확인된
결함을 두자는 뜻이 아니므로, 사용자 승인 후 **쓰지 않는 변수 한 줄을 지우고 지도 3장을
다시 만들었다.** 확인: 범례 4항목 / 표 1,800행(cross-fit) · 852행(test) · 143행(3개 주).

이 결함이 왜 오래 살아남았는지가 요점이다. `paint()`는 카운티를 **먼저** 칠하고
`legend()`를 나중에 부른다. 그래서 지도가 정상으로 보였고, 눈으로 봐도 "범례를 안 넣었나
보다" 정도로 넘어간다. `node --check`는 문법만 보므로 통과하고, 데이터 불변식 검사도
전부 통과한다. **실행 중인 DOM을 조회해야만 잡히는 종류**였다.

- **3개 주 지도 병기** — 전국 지도 하나로 충분하고, 두 장을 나란히 두면 z 스케일 비교
  경고를 또 붙여야 한다.

### 11-1. 라이선스 확인 결과 (2026-08-04)

**데이터는 CC BY-SA 4.0**이었다. share-alike이므로 파생물에 같은 조건이 따라온다 —
저장소를 `src/**` MIT / `outputs`·`reports`·문서·생성 HTML CC BY-SA 4.0으로 나눠
걸었다(`LICENSE`). 실제로 걸리는 지점은 `outputs/predictions/*.csv` 4개다(원자료 열
값을 행 단위로 담는다).

**서체는 SIL OFL 1.1**로 안내된다. 이 계획서가 "고지를 싣고 진행"을 기본값으로
뒀는데, 확인해 보니 그것만으로는 부족했다:

- OFL은 *"fonts and derivatives cannot be released under any other type of license"*
  라, 서체를 담은 HTML을 통째로 CC BY-SA로 배포한다고 적으면 **위반**이 된다.
  `LICENSE`에 **carve-out**을 넣어 번들이지 재라이선스가 아님을 명시했다.
- OFL 조항 2는 사본마다 **전문 동봉**을 요구한다. `--no_fonts`가 아닌 빌드는
  `_fontpack.license_comment()`가 `OFL.txt` 전문을 HTML 상단 주석으로 싣는다.
  링크가 아니라 임베드인 이유는 §1의 "외부 요청 0"을 라이선스에서 깨지 않기 위해서다.
- OFL 조항 3(Reserved Font Name)에 대비해 서브셋의 **내부 name 테이블**을 중립
  이름으로 바꿨다(`NSQ Subset`). CSS 패밀리명은 이미 `NSQ`였다. 예약 목록에
  `NanumSquare`는 없지만 첫 항목이 `Nanum` 자체라, 해석을 다투는 것보다 이름을
  바꾸는 편이 쌌다. 저작권인 nameID 0은 조항 2가 요구하므로 보존하고, 서브셋이
  떨어뜨리는 nameID 13/14는 다시 넣는다.

기록해 둘 불일치 하나: 배포처는 OFL로 안내하는데 **설치된 바이너리의 nameID 13은
`NAVER Corporation`, nameID 0은 `All rights reserved`** 로 OFL 표시가 없다. 위
조치들은 OFL로 읽든 네이버 자체 약관으로 읽든 양쪽에서 충족되므로, 확정되지 않은
것을 확정된 것처럼 적지 않고 `LICENSE`에 관찰로 남겼다.

**문체 (최종)** — 페이지 전체를 **보고서 평서체**로 통일했다. 중간에 한 번 짧은
구어형(-다/-음)으로 갔다가, 문제정의서와 같은 격식 있는 서술체로 되돌렸다. 최종 규칙:

- **본문**: 완결된 서술문, `~한다 / ~이다 / ~되었다`. 구어 표현(`~게 맞다`, `~뿐이다`,
  `노브를 더 돌리는`, `안 따짐`)은 제거.
- **제목**: `~다`로 끝내지 않고 **명사구로 종결**. "살인사건 열 건 중 세 건은 범인을 못
  잡는다" → "검거율 70.2%, 그리고 남는 29.8%", "격차를 학습 점수에 적어 넣는다" →
  "손실 함수에 기록한 공정성 제약", "설명이 안 되는 미해결은 어디에 쌓이는가" →
  "설명되지 않는 미제의 지리적 집중".
- **§01에 원자료 격차를 새로 넣었다.** 모델을 돌리기 전 단계의 근거이므로 문제 제기의
  핵심이다: 백인 피해자 74.1% 대 흑인 66.3%(7.8%p), 여성 76.9% 대 남성 68.3%(8.6%p).
  `clean.parquet` 전수(638,454건)에서 직접 재계산해 확인한 값이다 — 검거율 0.7020,
  White 0.7409 / Black 0.6628 / Female 0.7693 / Male 0.6832.

쉽게 쓰기와 격식 있게 쓰기는 충돌하지 않는다. **어려운 용어를 쉬운 설명으로 바꾸는 것**과
**구어체로 쓰는 것**은 다른 일이므로, 앞의 규칙(§1-4)은 그대로 유지한 채 문장 형태만
바꿨다. 여전히 SMR·BH FDR·충돌자 같은 용어는 쓰지 않고 풀어 쓴다.
