# 로컬 배포 계획서 — 클론하고 한 줄 실행하면 성적표 창이 뜬다

## 0. 한 줄 요약

`git clone` → `pip install` → `python -m experiments.dashboard` 세 단계로 **브라우저에
성능·공정성 대시보드가 뜬다.** 원본 데이터도, GPU도, 모델 가중치도 필요 없다 —
저장소에 이미 커밋된 결과 CSV 43개(13MB)와 평면 모델 예측 덤프 4개(8.4MB)만 읽는다.

### 확정된 것 (질문 4개의 답)

| 축 | 결정 |
|---|---|
| 화면 | **이미 나온 성적을 보는 대시보드** (학습 실시간 모니터링 아님) |
| 실행 | **HTML 생성 + 브라우저 자동 오픈** — 새 의존 0, 서버 불필요, 오프라인 동작 |
| 체크포인트 | **저장 기능만 추가**(`--save_model`), git 커밋은 보류 |
| README | **전면 개편** — 배포·재현 중심으로 재구성, 연구 서술은 `reports/`로 |

## 1. 먼저 정리해야 할 것 — 이 저장소에서 "배포"는 세 층위이고, 셋의 벽이 다르다

이걸 README에서 구분하지 않으면 **"다운받았는데 왜 안 돌아가지"** 가 첫 반응이 된다.
지금 저장소 상태를 그대로 적으면 이렇다.

| 층위 | 하려는 일 | 필요한 것 | 현재 가능한가 |
|---|---|---|---|
| **A** | 결과 확인 · 성능 검증 | **클론만** | **가능** (이번에 만들 대시보드) |
| **B** | 재평가 · 재학습 | + Kaggle 원본 CSV + 파이프라인 실행 | 가능하나 수 시간 |
| **C** | 새 사건 넣고 검거 확률 예측 | + 모델 서빙 | **의도적으로 만들지 않는다** |

**C를 만들지 않는 이유는 성능이 아니라 이 프로젝트가 이미 내린 판단이다.** 개별 사건
단위 출력은 (1) 재수사 결과 컬럼이 없어 **검증할 경로가 원리적으로 없고**, (2) MCC 0.30
에서 개별 사건 예측은 잡음이 지배하며, (3) 모델이 카운티를 모르는 것이 블록 단위에서는
의도된 설계지만 사건 단위에서는 오염이 된다. 지도 페이지의 유의사항 9번과
`experiments/audit_priority.py`가 같은 결론을 이미 문서화하고 있다. **"모델을 배포했다"를
개별 예측 API로 해석하면 프로젝트가 스스로 지킨 규율을 산출물에서 깬다.**

그래서 이 계획서의 "배포"는 **A층위, 즉 검증 가능한 성적표를 남이 자기 기계에서
재생하게 만드는 것**이다. 평가자가 실제로 원하는 것도 그쪽이다.

### 1-1. A층위가 성립하는 근거 — 무엇이 이미 커밋돼 있나

```
outputs/**.csv          43개 / 13MB   실험 기록 전체(성능·공정성·완화·적용·사후감사)
outputs/predictions/    4개 / 8.4MB   평면 모델 test 예측(재생성 불가라 예외 커밋)
```

`.gitignore`가 그림·지도 HTML·중간 산출물은 빼면서 **결과 CSV는 남기도록** 이미 설계돼
있다("작은 결과 CSV는 실험 기록이므로 커밋한다"). 이번 작업은 새 데이터를 만드는 게
아니라 **이미 커밋된 기록에 얼굴을 붙이는 일**이다.

### 1-2. 의존성 — 대시보드는 torch 없이 돈다 (확인함)

`config.py`는 `os`/`pathlib`만 import하고, `clear.results`는 pandas만 쓴다. 즉 대시보드
경로에 torch·torch-geometric·scikit-learn이 **전혀 필요 없다.** 이게 "3분 빠른 시작"이
성립하는 이유이므로, 의존을 분리한다:

```
requirements-dashboard.txt   pandas, numpy          # A층위 — 30초 설치
requirements.txt             (기존 그대로)           # B층위 — torch/PyG 포함
```

전체 `requirements.txt`를 깔게 하면 CUDA 안내와 `pyg-lib` 수동 설치까지 읽어야 하고,
그 순간 "다운받고 실행하면 창이 뜬다"가 거짓말이 된다.

## 3. 대시보드 설계

### 3-1. 커밋된 것만 읽는다 — 이게 규칙이다

`features.parquet`·`edges_*.npy`·미커밋 예측 덤프는 **건드리지 않는다.** 하나라도 읽으면
클론 직후 실행이 깨지고, 그 순간 이 산출물의 존재 이유가 사라진다. 검사 단계에서
`data/processed/`와 `dataset/` 접근이 없는지 기계적으로 확인한다(§6).

### 3-2. 패널 구성 — 6개

| # | 패널 | 읽는 파일 | 담는 것 |
|---|---|---|---|
| 1 | 예측 성능 | `results.csv` (family=train) | 모델 × 7지표, 시드 평균±표준편차, **마진÷노이즈 비율** |
| 2 | 공정성 진단 | `fairness_gaps*.csv`, `fairness_model_contrasts*.csv` | 증폭비, 짝지은 모델 대조, blind/sighted 대조 |
| 3 | 완화 트레이드오프 | `results.csv` (family=mitigate_*) | 정확도 vs 격차 산점도, α 사다리 |
| 4 | 그래프 진단 | `edge_homophily.csv`, `edge_relatedness*.csv` | 엣지가 민감속성 프록시인가, 관련성 리프트 |
| 5 | 적용 | `cold_blocks*.csv` | 상위 카운티 표, 잔차↔흑인비중 상관 |
| 6 | 사후 감사 | `resource_audit*.csv`, `shr_recording_*.csv`, `county_race_residual*.csv`, `priority_audit.csv` | 인력·정황·카운티 차분·우선순위 감사 |

**패널 1이 이 대시보드의 존재 이유다.** 단순 성능표가 아니라 **마진을 시드 표준편차로
나눈 비율**을 같이 낸다 — 이 저장소가 "어떤 지표로 이겼다고 말할 수 있는가"를 측정으로
결정한 것이 가장 특징적인 부분이고, 대시보드가 그걸 재현해서 보여줘야 평가자가 확인할
수 있다. `results.csv`의 `std` 열이 이미 있으므로 계산은 나눗셈 하나다.

### 3-3. 스코프는 나란히 두되 섞지 않는다

3개 주와 전국 결과가 **둘 다 커밋돼 있다.** 대시보드는 둘 다 보여주되 같은 표에 넣지
않는다 — 작동점이 다르고 모든 공정성 수치가 임계값 의존이라 직접 비교가 성립하지 않는다
(README·CLAUDE.md가 이미 세운 규율). 탭으로 분리하고, 탭 전환 시 **"두 스코프의 값을
직접 비교하지 말 것"** 문구를 고정 표시한다.

### 3-4. 지도는 대시보드에 넣지 않는다

카운티 지도를 그리려면 `dataset/geo/`의 GeoJSON(약 10MB)이 필요한데 이것도 gitignore
(재다운로드 가능)다. 첫 실행에 10MB 다운로드를 붙이면 **"클론 직후 즉시"가 깨진다.**
대신 패널 5에는 상위 카운티 **표**를 넣고, 지도가 필요하면 어떤 명령을 치면 되는지
안내한다. 표는 어차피 독립시(세인트루이스·볼티모어 등)를 읽는 유일한 경로이기도 하다.

### 3-5. 파일이 없으면 없다고 말한다

패널마다 필요한 CSV가 없을 수 있다(사용자가 `outputs/`를 지웠거나, 부분 클론). 이때
**빈 패널을 그리지 않고** "이 파일이 없다 → 이 명령으로 생성된다"를 표시한다. 조용히
빈 표를 그리면 "결과가 없는 프로젝트"로 읽힌다.

### 3-6. 재사용

`build_story_page.py`의 CSS 시스템·폰트 임베드(`_fontpack`)·자체 검사 골격을 그대로
쓴다. 다만 **대시보드는 밝은 배경**으로 간다 — 포트폴리오 페이지는 서사가 목적이라
어둡게 갔지만, 이건 숫자를 오래 들여다보는 화면이고 표가 지배적이다.

## 4. 체크포인트 — 저장 기능만 만들고 커밋은 보류

### 4-1. `state_dict`만 저장하면 못 쓴다

가중치와 함께 **모델을 되살리는 데 필요한 맥락 전부**를 같은 파일에 넣는다:

```python
{
  "state_dict": ...,
  "hyper": {hidden_dim, num_layers, dropout, aggr},   # 모델 재구성
  "feature_cols": [...],                              # X의 열 이름 순서 -- 아래 참고
  "blind": bool,                                      # 열 집합이 다르다
  "scope": "national", "edge_type": "geo", "k": 20,   # 어느 그래프에서 학습했나
  "seed": 42,
  "calibrated": False,                                # 아래 4-3
}
```

### 4-2. 열 순서를 반드시 저장해야 하는 이유

`03_features.py`가 원-핫을 만드는 순서는 데이터에 의존한다. 다른 기계에서 파이프라인을
다시 돌리면 열 순서가 달라질 수 있고, 그러면 **가중치가 엉뚱한 특성에 붙는다.** 지표는
그럴듯하게 나오고 오류는 안 난다 — 이 저장소가 `--blind` 무음 no-op에서 이미 한 번
당한 종류다. 그래서 로드 시 열 이름 순서를 대조하고 **불일치하면 죽는다.**

### 4-3. `calibrated: False`를 왜 파일에 적나

`clear.gnn`은 `pos_weight`로 학습해서 예측이 **순위는 맞지만 확률로는 치우쳐 있다**
(전국 기대 미제가 관측보다 +47.9% 많다). `detect_cold_blocks`는 로짓 이동 δ로 보정한
뒤에야 쓴다. 체크포인트를 받아 확률로 바로 쓰는 사람이 반드시 생기므로, 파일 안에
"보정 안 됨"을 적고 로더가 그 사실을 출력한다.

### 4-4. 커밋을 보류하는 이유

가중치는 약 2.4만 파라미터, 3시드 합쳐 **약 300KB로 LFS도 필요 없다.** 그런데도 보류
하는 이유는 **클론만 한 사람은 그래프도 특성도 없어 쓸 수가 없기 때문이다.** 못 쓰는
파일을 저장소에 넣으면 "모델을 배포했다"는 인상만 주고 실제로는 아무 것도 안 된다.
데이터를 가진 사람에게는 재학습(수십 분)을 면하게 해 주므로 **기능은 만들어 두고**,
커밋 여부는 나중에 판단한다.

## 5. README 전면 개편

### 5-1. 새 구조

```
CLEAR — 한 줄 소개
├── 빠른 시작 (3분)          ← 새로 맨 앞
│   1. 클론  2. 설치  3. 실행 → 창이 뜬다
├── 성능 지표                ← 새로. 표를 여기 박는다
│   예측 / 공정성 / 완화 3개 표
├── 무엇이 되고 무엇이 안 되나  ← 새로. §1의 3층위 표
├── 전체 재현                ← 기존 "실행" 섹션 이동
│   데이터 받기 → 파이프라인 → 실험
├── 프로젝트 구조            ← 기존 유지
├── 결론과 한계              ← 기존 "결론 한 줄" 확장
└── 문서                     ← reports/ 링크 목록
```

기존 README의 연구 서술(스코프 설명, 누수 제약 등)은 **지우지 않고 뒤로 옮긴다.**
지금 순서의 문제는 내용이 아니라 **처음 온 사람이 무엇부터 해야 하는지가 6번째 섹션에
있다**는 것이다.

### 5-2. 성능표는 손으로 적지 않는다

README에 숫자를 하드코딩하면 재실행 때 조용히 어긋난다. `dashboard.py`에
`--emit_readme_tables` 를 넣어 **`results.csv`에서 마크다운 표를 생성**하고, README의
지정 구간(`<!-- METRICS:START -->` … `END`)만 갈아끼운다. 숫자의 출처가 파일 하나로
고정되고, 어긋나면 재생성으로 고쳐진다.

### 5-3. 스크린샷

README 맨 위에 대시보드 스크린샷 1장. `outputs/*.png`는 gitignore이므로 `docs/` 아래에
따로 둔다(예외 규칙 추가).

## 6. 검증

`build_story_page`가 쓰는 방식을 그대로 따른다.

**자동(빌드 시 항상)**
1. **클론 직후 시뮬레이션** — `data/processed/`와 `dataset/`을 임시로 안 보이게 하고
   대시보드를 생성해 성공하는지. 이게 이 산출물의 핵심 계약이므로 검사도 여기에 건다.
2. `node --check`로 인라인 JS 문법.
3. 외부 요청 0(base64 제외), 파일 크기 상한.
4. 숫자 대조 — 대시보드에 찍힌 값 == CSV에서 재계산한 값.
5. 패널마다 "파일 없음" 경로가 실제로 안내 문구를 내는지(파일을 하나 숨겨서 확인).

**브라우저(헤드리스)**
6. 렌더 후 스크린샷 확인 + DOM 조회로 탭 전환·표 행 수 확인. 지도 3장에서 범례가 통째로
   비어 있던 결함이 **DOM 조회로만 잡혔다는 전례**가 있으므로 생략하지 않는다.

### 6-1. 실제 구현 현황 (2026-08-04)

계획과 구현이 어긋나 있었으므로 여기에 정확히 적는다.

| 항목 | 상태 |
|---|---|
| 1 클론 직후 시뮬레이션 | ✅ `--verify_clone`. 실제로 두 번 실패를 잡았다(`OFL.txt`·`_htmlcheck.py`가 빌드 입력이 되었는데 미추적이던 때) |
| **2 `node --check`** | ✅ **2026-08-04 배선.** 그전까지는 **호출부가 저장소 어디에도 없었다** — 개발 중 손으로 한 번 돌린 것이 문서에는 자동 검사로 적혀 있었다. `experiments/_htmlcheck.py` 참조 |
| 3 외부 요청 0 · 용량 상한 | ✅ |
| **4 숫자 대조** | ⬜ **미구현** |
| **5 "파일 없음" 경로** | ⬜ **미구현** |
| **6 헤드리스 DOM** | ⬜ **미구현** — 이 목록에서 유일하게 §7-3의 결함을 잡을 수 있는 항목이다 |

`node --check`는 **문법만** 보므로, 배포까지 갔던 `legend()`의 `ReferenceError`는
이것으로 잡히지 않는다(그 코드는 문법적으로 유효했다). 2번을 배선한 목적은 구멍을
메우는 것이 아니라 **문서와 현실의 불일치를 없애는 것**이다. 구멍은 6번이 메운다.

`node`가 없는 기계에서는 검사를 건너뛰되 그 사실을 출력한다 — 대시보드는
`pandas + numpy`만으로 돌아야 한다는 계약(§1)이 있어 node를 하드 의존으로 만들 수 없고,
"없어서 건너뜀"과 "검사해서 통과"는 다른 사건이므로 구분해 찍는다.

---

## 7. 하지 않을 것

- **개별 사건 예측 API/UI** — §1의 이유. 요청이 와도 이건 별도 판단이 필요하다.
- **학습 실시간 모니터링** — 이번 범위 밖(질문에서 확정). 필요해지면 `train_gnn`의
  에폭 로그를 같은 HTML 골격에 얹으면 되므로 확장 경로는 열려 있다.
- **Streamlit/Plotly 도입** — 새 의존이 "3분 빠른 시작"을 깨고, 저장소가 지켜온
  "차트 라이브러리 없이 직접 그린다" 규율과 충돌한다.
- **체크포인트 git 커밋** — §4-4. 기능만 만든다.
- **지도 자동 다운로드** — §3-4.

## 9. 구현 결과 (완료)

1~5 전부 구현했다. 작업 순서 자체는 아래 §10 그대로 갔다.

### 계약이 실제로 성립하는지 확인했다

`--verify_clone` 이 **git 추적 파일만 복사한 임시 트리에서** 대시보드를 빌드한다.
`dataset/`도 `data/processed/`도 없는 상태에서, 폰트가 있는 기계와 없는 기계 양쪽
모두 `exit=0`. 계획서에 "즉시 중단 사유"로 적어 둔 조건을 명령 하나로 고정했다.

### 자체 검사를 소스 grep에서 런타임 추적으로 바꿨다

처음에는 스크립트 소스에 `data/processed` 같은 문자열이 있는지 봤는데, **문서 주석에
그 경로 이름이 나온다는 이유로 4건이 거짓 실패**했다. 지금은 `load()`가 연 경로를
전부 기록하고 그것만 검사한다 — 주석은 안 걸리고, 주석 없이 몰래 읽는 경로는 걸린다.

### 렌더가 잡아낸 데이터 오류 둘 (패널 1)

둘 다 표가 그럴듯하게 나오는 종류라 눈으로 봐야 걸렸다.

- **`std` 열은 train 행에서 항상 비어 있다.** `results.csv`는 시드별로 한 줄씩 남기고
  집계는 읽는 쪽이 한다. 그대로 믿었더니 표준편차가 전부 `-`로 나오고 마진÷노이즈가
  통째로 무의미해졌다. 지금은 시드에 대해 직접 std를 낸다.
- **설정 키를 다 안 쓰면 다른 실험이 한 줄로 섞인다.** 3개 주 blind geo에는 기본
  (shuffle) 말고도 랭킹 그래프와 그 차수 맞춤 대조군이 같은 model/tag/edge_type으로
  들어 있다. `edge_mode`를 빼고 묶으니 0.2659 / 0.2628 / 0.2574가 평균돼
  **0.2620이라는 어디에도 없는 숫자**가 표에 올랐다. tag도 substring으로 보면
  `fairness_handoff`가 기본 sighted와 합쳐진다. 지금은 설정 키를 전부 라벨에 담고,
  값이 문서와 정확히 일치한다(0.2854 / 0.2659 / 0.2574 / 0.2628 / 0.2494).

같은 계열로 대조표에 `group_set`이, 인력 감사표에 `measure`가 빠져 **같은 행이 두 줄로
보이던 것**도 고쳤다.

### 마진÷노이즈의 절대값은 시드 수에 민감하다

여기서 계산한 MCC 비율은 99.4배로, 보고서의 19.0배와 다르다. 표준편차를 `results.csv`에
남아 있는 시드(3개)로만 내기 때문이다. 그래서 화면에 **"비율의 절대값보다 지표 사이의
순서를 보라"**를 붙였다 — 어느 지표가 노이즈를 넘고 어느 지표가 못 넘는지가 판단 대상이고,
그 순서는 두 계산에서 같다.

### README

전면 개편했고 `METRICS` 마커 사이는 `--emit_readme_tables` 가 채운다. 손으로 적은 숫자가
없으므로 재실행 결과와 어긋날 수 없다. 생성된 값은 문서와 일치한다(전국 인종 증폭비
1.805 → 0.337, 성별 1.246 → 0.915, 카운티 1,803 / 74 / +0.290).

### 체크포인트

`train_gnn --save_model` 로 시드별 `.pt` 를 저장한다. `state_dict` 와 함께 하이퍼파라미터,
**특성 열 이름 순서**, blind 여부, 스코프, `calibrated: False` 를 같이 넣고, `load_checkpoint`
가 열 순서를 대조해 다르면 죽는다. `.gitignore` 에 `outputs/models/` 를 추가했다 — §4-4의
이유로 커밋하지 않는다.

## 10. 작업 순서

1. `requirements-dashboard.txt` + `dashboard.py` 골격 + 패널 1(예측 성능)
2. 패널 2~6
3. 클론 직후 시뮬레이션 검사
4. `--emit_readme_tables` + README 전면 개편
5. `clear.gnn` 체크포인트 저장/로드 + `train_gnn --save_model`
6. 헤드리스 렌더 확인

1~4가 "다운받고 실행하면 창이 뜬다"의 전부이고, 5는 독립적이다. **1~4를 먼저 끝내고
동작을 확인한 뒤 5로 간다.**
